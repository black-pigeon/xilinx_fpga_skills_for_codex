# U230 实践来源与项目适配

## 提炼依据

从用户现有 U230 SDR/PCIe 工程的实际脚本和调试记录提炼，核对日 2026-11-11。下列均为**项目相对路径**，不是安装本技能的必备文件，也不保证其他机器存在。运行时从当前项目定位；不要复制过去的绝对目录、临时工具路径或密码。

- `verification/u230/evidence/P3/tx-timed-duplex-retest-20261111/program.tcl`：目标数检查、Artix-7 设备选择、6 MHz JTAG、下载后退出。
- 同目录 `run-board.py`、`README.md`：先核对已实现镜像和基线，下载前后协调 PCIe，失败后恢复健康 RX，再复测控制与 AD9361。
- `fpga/scripts/vivado/capture_duplex_debug.tcl`：同一会话 arm/collect、导出原始 probe map、刷新异步状态、有限等待、拒绝非 FULL 导出。
- `verification/duplex_debug/test_capture_tcl.py`：用 fake Hardware Manager 离线验证触发比较、映射和非 FULL/异步状态等边界。
- `verification/u230/evidence/P3/tx-bar-debug-20261111/reset-census/capture-bar-ila.tcl`：先设匹配 LTX，记录器件监测与探针，再用 BAR RX valid 触发。
- `verification/baselines/2026-11-06-wrapper-axis-board/verify_configuration.tcl`：已有 bit 与匹配 mask 的只读配置验证，与编程和 PCIe 变更分开。

这不是对整个项目脚本逐字复制：来源包含机器与实验特有内容，新技能只提炼公共机制并重写可配置工具；可移植工具未连接板卡复测。

## 本项目已观察的条件

- 来源实验使用 Artix-7 `xc7a200t`、Vivado 2022.2、已有 `localhost:3121` hw_server、Digilent 线缆；这不是全部 Xilinx 器件的固定默认。
- 6 MHz 是来源实验的 JTAG 选择；使用其他线缆/长链或排障降频时需明确实验目的，不对所有任务自动改频率。
- 来源部分下载脚本有 `open_hw_target -jtag_mode on/off`，它是该实验的特定连接处理，不强加到所有连接。通用工具正常打开准确 target，失败再检查项目依据。
- 本项目存在另一聊天持续上板实验的情况。创建/测试 skill 时只离线检查，没有抢占其 cable、抓取、改镜像或恢复板卡。

## U230 的测试与恢复顺序

复用项目当前的辅助工具，先查当前有效路径和参数，再执行：

1. 记录板上 BUILD_ID、PCIe link/driver、DMA 状态及健康基线镜像。
2. 有重配需要时先停 DMA/用户进程，按项目流程移除 PCIe 功能；不得在活跃 DMA 下盲目配置 FPGA。
3. 选择准确设备下载候选 bit；必要时做独立配置回读，记录每个阶段而不是混成一个 pass。
4. 按项目步骤重新枚举，核对 BDF/vendor/device、link、驱动与 BAR 能力标识。BDF 不能硬编码为历史值。
5. 控制自检/寄存器 ID 成功后，再做所需 RF 初始化、PN/回环、有限 DMA 和业务刺激；某个前置失败就停止后续依赖实验。
6. ILA 实验先核对对应 bit/LTX、时钟与 probe map，布防后再发有限刺激；抓取不自动等于启用 RF 发射。
7. 候选失败时，使用已知健康镜像及项目恢复流程，复测控制和必要业务，并明确最终保留哪一版。

项目曾出现“bit 下载成功，但 PCIe 能力寄存器为全 1、驱动绑定失败；恢复 RX 基线后控制与 PN 又正常”的情况。应把故障定位在已验证的阶段边界，不能把恢复后的成功算成候选通过，也不能在 BAR 尚未工作时归因于后级 IQ/射频业务。

## 推广到其他板卡

先适配器件、线缆、Vivado/hw_server 版本、镜像与 LTX 来源、时钟/复位、业务刺激和恢复方案。Zynq/MPSoC/Versal 的启动、处理器、PL 配置依赖不等同于本 Artix-7 PCIe 流程；不要直接执行本项目的 PCI remove/rescan、AD9361 或驱动步骤。
