# FPGA RTL 编码规范

将团队《Verilog-AI 硬件协同设计规范》V1.2、用户补充和 AMD UG949 v2025.1 转化为可综合 RTL 约束。默认面向多厂商 FPGA，通用 RTL 优先保持可移植；厂商明确后才按对应器件/工具采用专用能力。FIFO 默认沿用 Ettus/UHD 在 N310/X4xx 中的公共模块分层与 ready/valid 用法；需要 Xilinx IP 时，通过 Tcl 在现有工程中创建和添加，不把该选择推广到其他厂商。团队命名/结构默认与器件方法论分开，不能以风格规则妨碍正确的资源推断。

## 触发边界

仅当当前任务需要生成、修改或重构**可综合的 RTL 实现**时自动调用。根据代码用途判断，不能只凭 `.v`/`.sv` 扩展名或出现 Verilog/SystemVerilog 字样触发。

仅写 testbench、UVM、验证用 SVA、仿真脚本、非综合参考模型/软件、阅读讲解或独立代码审查时，不自动调用。用户显式指定本 skill 做规范审查时，可按指定范围只读检查。

同一任务同时编写 RTL 与测试时，仅将编码约束用于可综合 RTL；testbench、验证断言及仿真辅助代码可正常使用 `initial`、延时和验证专用结构。编写 RTL 时的自查和必要验证仍属于流程。

## 应用顺序

1. 读目标文件、调用方、项目说明及已有构建命令。确定 Verilog/SystemVerilog 版本、复位、接口协议、位宽/符号/定点格式、吞吐率和已有延迟契约。
2. 阅读 [references/rtl-rules.md](references/rtl-rules.md)；面向 Xilinx/AMD Vivado 时再读 [references/xilinx-ug949.md](references/xilinx-ug949.md) 的相关主题。优先级为：用户明确要求 → 已有接口/协议/功能契约与器件合法性 → 目标器件方法论 → 团队结构/风格默认。显式要求与器件能力冲突时说明，不能静默生成无法实现的电路。
3. 新模块采用下列默认约束；已有模块做局部修改，保留外部端口名称、复位语义、握手和延迟。新增寄存级、超时、CDC 或握手必须纳入明确的行为设计，不能作为静默风格修复。
4. 设计前明确目标时钟/吞吐和关键路径预算，并考虑寄存边界、扇出与布线局部性。涉及 FIFO 时先阅读 [references/ettus-fifo.md](references/ettus-fifo.md)：默认复用可追溯的 Ettus/UHD 公共 FIFO，不为每处队列重新手写存储指针；同步使用 flop/SRL/BRAM 分层，跨域使用核对过的异步封装及目标器件 IP。保持容量、复位、时间戳 bundle 和排空契约，不能假定直接替换兼容；不适用时说明具体差异并选择已验证实现。
5. 需要 Xilinx FIFO IP 时沿用现有 Vivado 工程，通过可重复执行的 Tcl 创建/添加源码和 IP、核验配置并生成仿真及综合产物；保留上游来源、许可证、IP 配置和依赖。已有同名 IP 配置不符时明确报错，不能静默覆盖或升级。具体流程见上述参考，不因迁移 FIFO 新建工程或约束文件。
6. 交付前核对受影响规则，执行项目已有编译、lint、自检仿真；对改动的组合判定逐信号/位确认所有路径都赋值，仿真覆盖从命中分支转到所有条件均不命中及分支重叠，核对复杂条件的显式分组；无 latch 告警不能代替路径检查；FPGA 功能改动先完成仿真再进入综合/bit 构建，仿真失败不得下载试错；工具不可用时说明而非跳过门槛。没有运行综合/实现、STA 或 CDC 检查，就不声称对应检查通过。

## 新模块默认约束

- **命名**：自定义端口 `i_`/`o_`；内部寄存器 `r_`、输入寄存器 `ri_`、输出寄存器 `ro_`、连线 `w_`；参数和状态 `P_`；数组 `_array`。AXI 等标准接口保持原生/项目既定名称。
- **复位**：逐组判断运行时复位需求；需要复位的普通单时钟寄存器默认同步高有效，复位优先于使能。状态、valid/占用等控制须恢复到安全值；不机械复位全部 payload、RAM 或延迟线。无复位数据必须被有效标志隔离且在使用前覆盖，既有输出清零契约保留；复位与无复位寄存器分过程，避免隐式 CE。时序块首分支 `if (i_rst)` 只做运行时复位，abort/flush/事务结束等业务清零在同一块中按原优先级写成后续 `else if`，禁止 `if (i_rst || w_abort)` 及混入业务条件的复位别名。此规则无需新增组合次值或使能过程。同一寄存器只有一个时序驱动。配置初始化不能替代运行时复位（R02/R08）。
- **边界**：新普通数据通路默认 `ri_` 输入寄存、`ro_` 输出寄存，再用 `assign` 驱动自定义输出。时钟/复位不作为普通数据打拍；握手、存储读口和已约定零延迟路径按协议设计。`assign` 本身不增加寄存级或改善时序。
- **时序**：时序块用非阻塞赋值；每个时序 `always` 块默认最多更新 3 个独立寄存器变量，按数据/控制职责拆成小块；同一握手 bundle 的有效性清除、更新/停顿和逐拍对应关系必须一致，不能为了凑数量破坏对齐；payload 与 valid 可有不同物理复位，但须满足前述有效性隔离。宽向量算一个变量；不以拼接/结构体藏起无关状态来规避上限，也不为拆块制造独立 CE/复位。此项是团队可读性规则，不是 AMD 时序门槛。每个变量只有一个过程驱动。SV 使用 `always_ff`/`always_comb`，Verilog-2001 使用相应合法语法。
- **组合逻辑**：`always_comb` / `always @*` 中，每个组合输出和临时变量（含被分段赋值的位）必须在所有路径上确定赋值。`if/else if` 链优先写出定义回退行为的最终 `else`；只有在块入口已完整设定默认值、分支只做覆盖时，才可省略。不能用 `q = q`、空 `else` 或只补 `valid` 掩盖漏赋值。时钟沿触发的时序块可有意省略 `else` 表达寄存器保持。
- **时序分支结构**：每个时序 `always` / `always_ff` 块仅用一条 `if / else if / else` 决策链组织条件更新；允许链内嵌套，但任何同级语句序列不得出现相互独立的多个 `if`。不同寄存器需要同拍独立更新时按职责拆成独立时序块，保持单一驱动、复位、使能和边沿行为；同一寄存器原有多个非阻塞赋值时，先确认后写覆盖的优先级再改写。不得直接把并列 `if` 改成 `else if` 而漏掉同时成立的更新；寄存器保持可省略末尾 `else`，不要增加空分支或自赋值。见 R02。
- **条件表达式**：`if`、`?:` 等的复合判定混用不同运算符时，必须在内部用括号明确分组，例如 `if ((i_len != 0) && (i_ready || i_force))`。外层 `if (...)` 不算分组；整理既有代码时保持原有求值和仲裁顺序，语义不明先核对。见 R06。
- **组合表达式长度与结构**：可综合 RTL 不写嵌套或串联的 `?:`；只用单层 `?:` 表达简单二选一。复杂判定拆成有语义的 `w_` 条件和候选值；有优先级的多路选择用显式 `if / else if / else`，多字段拼接先命名复杂字段。时序块仍遵守单条件链，保留原有优先级、复位、保持和边沿延迟。见 R06。
- **数据流**：data/valid/控制信息逐级同步；有背压时整级一致停顿，valid 在接收前保持，数据在等待期间稳定。复位清除流水有效状态。
- **运算**：明确 signed、操作数扩展、中间位宽、累加增长和定点缩放；切片后按需恢复 signed。不要照抄来源示例中的缩位或缩放。
- **FSM/CDC**：FSM 的状态寄存/转移逻辑与数据通路处理逻辑分开；状态机有组合默认赋值、`default` 和确定恢复路径；三段式是建议。单比特电平、脉冲和多比特跨域分别选择匹配方案；不能统一加两级触发器。
- **初始化与可移植性**：可综合 RTL 默认避免 `initial`、寄存器声明初值和器件 INIT/GSR 依赖；需要确定初态时优先显式复位或启动/填充协议。无复位 payload 通过写入覆盖和 valid 隔离保证正确，不假设上电为零。只有当前功能确需 ROM/存储预置等、且目标器件/工具已确认支持时才采用初始化例外，说明用途和移植代价；不因 Vivado 支持就自动使用。testbench 不受此限制。
- **资源映射**：按目标厂商/系列模板推断存储、延迟线和运算资源；面向 Vivado 时再考虑 RAM/SRL/DSP 与 XPM/IP/原语。保护目标资源的寄存器吸收条件；不能为避免 INIT 而给整块 RAM 或所有数据级机械加复位。
- **时序与布线**：按目标时钟预算控制单拍的逻辑级数，避免在同一端点串联长算术、宽比较和多级优先 mux，并关注高扇出与布线局部性。换行、拆 wire 或改分支语法不等于缩短路径；用实现后的对应路径报告核对。真要加寄存级，先确认允许的延迟以及 data/valid、握手和时间戳的逐拍对齐。见 R09。
- **控制与属性**：区分真正的优先级和互斥选择；不把 `casex`/`parallel_case` 当成优化模板。先减不必要负载，再按报告处理高扇出；不复制 CDC 同步级，不随意加 `DONT_TOUCH`、`MARK_DEBUG`、`MAX_FANOUT` 或时序例外。
- **风格**：模块头说明功能、时钟/复位、格式、延迟、吞吐及关键状态。局部对齐，不重排无关代码；以解释关键意图代替凑注释行数。

## 按任务补充

- 生成：接口和性能要求不充分时，先给出少量必要假设；不虚构频率、DSP/BRAM 数量、综合结果或 Transformer 架构。
- 修改：检查新增级数对 data/valid、使能、帧边界及调用方的影响。规范无法兼容既有契约时保留契约并解释具体差异。
- 设计性能敏感 RTL：先找目标时钟、时序约束和关键路径；优先结合综合/布局布线、STA、扇出和拥塞报告调整结构。缺少目标器件或约束时明确假设，不虚构 Fmax、资源或布线效果。
- RTL 编写自查或用户显式指定的规范审查：按“功能/协议/时序风险 → 条件性规范差异 → 风格建议”报告，给出文件与行号、影响及修复建议；只读审查不改代码。

交付说明保持简短：列出假设/例外、接口与精确边沿延迟、已运行检查及未验证项。修复每个发现的问题后再完成最终核对。
