## 1. 开始写 RTL 前

明确目标器件/系列、Vivado 版本、真实时钟/关系、吞吐与可接受的流水延迟、资源/功耗需求、运行时复位及启动行为。优先复用项目约束和同版本 Language Templates。UG949 提供决策方法；精确端口、宽度、参数及推断语法仍需对应架构/UG901/库指南。

- 模块边界围绕相关功能和时序路径；可在契约允许的边界寄存，但不机械地给每个 wrapper 再加一级。
- I/O 缓冲、DDR/SerDes 与时钟资源尽量靠近顶层规划；共享可共享的时钟资源。推断 IOBUF 时，数据、使能和双向关系不能被保留层级隔断。
- 保留 RAM/DSP 及其目标内部寄存器的推断整体。把文件拆小和把路径变短是不同的事；层级本身不保证布局紧邻。
- 跨 SLR/长物理距离的设计才结合器件布局规划流水与分区；小模块不默认加入 Pblock 或物理锁定。

## 2. 复位、初始化与控制集

先区分三件事：配置时 INIT、运行时 reset、存储内容擦除。GSR/INIT 不能替代中途复位、协议恢复或安全启动时序；硬件初值不能假定为仿真中自动存在。

- 逐组说明为什么需要复位。状态、valid、占用/指针和控制须进入安全状态；纯 payload 在使用前必被覆盖、且无效内容不会影响控制或外部接口时，可不复位。协议规定 invalid 时保持/清零的输出仍遵守契约。
- 需要复位时优先考虑同步复位，优先级置于 CE 之前。外部异步断言按系统需求保留，释放同步到各目的时钟，并处理时钟尚未稳定的启动过程。
- 无复位数据通路与有复位控制分过程。不要仅注释掉同一个 `if (reset)` 内的 payload 赋值：留在 `else` 下的更新会形成 reset 期间的保持条件，可能引入 CE（p.44 图 22/23）。不要为删复位而制造同一变量多个过程驱动。
- 控制集由实际 clock/reset/enable 组合决定。拆成多个 `always` 但保持同样控制不会因过程数量本身增加控制集；各块另造独立 CE/reset 才可能增加控制集种类并限制装箱。
- CE 用于真实保持/背压或功耗需求。若小组数据 invalid 时任意且无保持约定，可评估常更新或确定赋值减少 CE；宽总线保持可能有功耗收益，不能普遍去使能。
- 不为上电清零而给整个 RAM 或深延迟线增加复位。确需运行时擦除存储时，设计逐地址清零/有效位方案及完成条件；未满足擦除要求前不能报告已完成。
- Xilinx 支持的寄存器声明初值、特定可综合 `initial`/存储初始化属于配置机制；记录目标与文件依赖，不扩展成任意行为 `initial` 均可综合，也不推广到未知 FPGA/ASIC。

**团队规则边界**：最多 3 个独立变量/时序块、命名前缀和 FSM/数据通路分离来自团队要求，不是 UG949 强制项。资源模板或相关协议状态超过上限时说明必要例外；不通过无意义拼接、额外流水或不同控制掩盖问题。

## 3. 按资源选择 RTL 结构

| 资源 | 设计/检查重点 | 应避免的机械做法 |
|---|---|---|
| BRAM/LUTRAM | 读写端口/时钟、同步或异步读、冲突语义、读延迟；按目标模板推断，检查实际资源数量和读输出寄存器 | 整阵列 reset；认为 `ram_style` 一定覆盖不兼容的行为描述 |
| BRAM 输出寄存器 | 与阵列尽量同层级；检查直连、扇出、反馈、复位及 CE 兼容性，核对原语输出寄存器是否启用 | 在吸收边界插组合逻辑、额外分叉/调试属性或异步 reset；把“两级”固定成所有 RAM 的读延迟 |
| DSP | 明确符号/全精度；在延迟允许时利用输入、乘积和输出流水；核对目标系列的内部同步复位/置位能力 | 对映射寄存器强加异步复位或置位；把某系列的乘法宽度当成所有 DSP 限制；为了 signed 映射改变数值语义 |
| SRL | 深延迟线评估 SRL；需要较快 clock-to-out 时考虑末级 FF；按 valid/填充时间隔离启动或复位后旧内容 | 每一级 reset；认为写了任意移位代码就能保持目标 SRL 映射 |
| URAM/大存储 | 先确认系列确有资源，再定端口/时钟、读取延迟和级联布局，必要时选 XPM | 对 7 系列直接推荐 URAM；照搬 UltraScale+ 的级联参数或频率承诺 |

优先推断；不支持的功能或映射结果不能满足要求时，再根据证据选 XPM、IP 或原语，并包含仿真依赖。声明属性只是意图，综合后网表/资源报告才证明实际映射。

## 4. 流水线、扇出与物理局部性

- 早期规划关键算术、宽 mux、大扇入和跨物理区域路径。每一级同时列出数据、valid、last/标签及背压更新事件；分离 FSM 与 datapath 不得引入首末拍偏差。
- 插入流水要有延迟和吞吐预算。无必要的宽流水可能增加 FF、控制网与拥塞；SRL 能节省面积但不适合所有跨区分发。不能依据 UG949 的示例 MHz/逻辑层数估算宣称设计达标。
- 先删除不必要负载/复位/控制，使用综合后的 `report_high_fanout_nets`，并结合布局后的路径分析再处理高扇出。总扇出数字不等于关键路径严重程度。
- 必要时按本地负载分组复制驱动，或利用布局/物理优化。不要对全局 reset/enable 普遍贴 `MAX_FANOUT`；不要全局降低阈值来替代诊断。任何分级/复制须保持各分支逻辑值、复位释放和周期关系。
- 不复制 CDC 同步链，不能从未稳定的级分叉；同步后确需额外分发寄存时，明确新增延迟。不要用 `DONT_TOUCH` 妨碍后续物理优化来“保证复制”。
- 无优先级的互斥译码可用清晰的 `case`；真正优先仲裁保留优先语义。p.65 的 `casex`/`parallel_case` 是特定示例，不能作为通用模板；未知值、重叠选择、非法状态和仿真/综合一致性仍须处理。

## 5. 时钟、CDC 和约束

- 时钟门控/切换采用目标系列专用资源及合法控制方法；不以 LUT 的与/或/普通 mux 直接驱动时钟。局部数据保持与整域关钟是不同需求。
- 区分同源同步派生时钟与异步时钟。完整定义主/生成时钟、端口 min/max 延迟及适用例外，不能把所有异频时钟一律切成异步。时钟资源/反馈结构按目标器件指南检查。
- CDC 按电平、脉冲、复位、多比特一致性/速率选择结构。可选 XPM 单比特/脉冲/复位同步器、Gray、握手或异步 FIFO；普通多位逐位同步仅用于位间无需相关性的信号。
- 计数器的 Gray 跨域必须满足编码/源端更新及总线时延偏差条件；握手的源数据需保持至完成。同步级数来自速率、可靠性与延迟需求，不普遍固定两级。
- `ASYNC_REG` 应用于真正同步级；适用时检查目标工具支持的 CDC/MTBF 报告。`report_cdc`、MTBF、STA 和功能仿真解决不同问题，不能互相替代。
- `set_false_path`/异步时钟组不是 CDC 电路；multicycle 必须有真实采样/使能依据并核对 hold 与所有受影响路径。禁止通过改周期、删除路径或抑制告警伪造收敛。

## 6. 综合属性与调试代价

`KEEP`、`DONT_TOUCH`、`KEEP_HIERARCHY`、`MARK_DEBUG`、`MAX_FANOUT`、`USE_DSP`、`RAM_STYLE`、`SHREG_EXTRACT` 只在需要且适用于目标时使用，记录对象和目的。它们可能限制重定时、寄存器吸收、合并/复制或跨层优化。

- 不为排版、层级可见性或尚未使用的 ILA 大范围保留信号。调试属性/核改变后，重新检查资源及时序。
- 确需阻止 SRL 以支持物理流水时说明局部理由；不要全局关闭 SRL/RAM/DSP 推断。
- 不因正文包含属性/约束示例就自动给当前工程添加。工具版本不同时先查本机帮助/对应文档；不要照搬默认阈值和架构特有参数。

## 7. 按设计阶段验证

按本次修改和已有工程流程选择检查，不要求每个小改动重新做全芯片实现。

| 阶段 | 应得到的证据 | 不能据此宣称 |
|---|---|---|
| RTL/细化 | 编译、lint、自检仿真、适用的 `report_methodology`；启动/中途 reset、invalid 屏蔽、背压和状态边界 | 已满足器件频率、CDC MTBF 或布线要求 |
| 综合 | 日志/DRC/方法论、资源及原语寄存器映射、控制集/高扇出、CDC、时序约束覆盖 | 已按布局布线收敛 |
| 布局/布线 | 方法论/DRC、拥塞与实际关键路径，建立/保持及脉宽、时钟/I/O 和异常路径检查 | WNS 非负就等于系统功能正确 |

复用项目报告脚本；在打开相应阶段的设计后，可按适用范围使用 `report_methodology`、`report_drc`、`report_utilization`、`report_control_sets`、`report_high_fanout_nets`、`report_cdc`、`check_timing` 和 `report_timing_summary`。参数和对象应按当前 Vivado 帮助/工程设置核对，不复制无效通配选择器。

显著结构、时钟或约束变更后复查。严重警告应修复或有据豁免；不能降低告警等级掩盖问题。STA 验收应检查无时钟/未约束内部端点为零以及 I/O/异常覆盖是否正确，不能只检查 setup WNS，也不能认为“全约束”就证明约束值正确（p.167）。

## 8. 容易误用的场景

| 当前请求/约束 | 应采取的做法 |
|---|---|
| 深 payload 延迟线希望节省 FF，控制支持运行时 reset | 将有效性控制与数据分开；分析何时数据重新有效，再评估 SRL，不为每级强加 reset |
| RAM buffer 必须在运行时清零 | 保留清除需求，设计清零完成流程；不能用 INIT 替代，不能借优化直接取消清零 |
| 目标是 7 系列，要求大容量缓存 | 按 BRAM/LUTRAM 及真实器件资源评估，不能推荐不存在的 URAM |
| AXIS 阻塞时数据必须稳定 | 保留持有/CE 或弹性缓冲；减少控制集不能破坏稳定性 |
| 拆分包含 5 个变量的时序块 | 同时检查 reset/enable/单驱动和资源模板；最多 3 个变量是团队默认，保留必要模板需说明 |
| 异步状态总线扇出大 | 先判断各位相关性和正确 CDC，再处理稳定输出的分发，不能复制同步级 |
| 仅需整理模块层级 | 不默认加流水、`DONT_TOUCH`、ILA 或物理约束；保持接口和路径契约 |
