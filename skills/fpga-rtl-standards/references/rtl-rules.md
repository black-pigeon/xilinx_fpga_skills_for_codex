# FPGA RTL 规则清单

自动调用仅适用于生成、修改或重构可综合 RTL；仅有测试/验证代码、讲解或独立审查的任务不自动触发。混合任务只约束其中可综合 RTL。

“默认”适用于新建、接口未固定的模块；“必要”用于保证所声明的功能和协议正确；“建议”可按项目覆盖。来源为团队 PDF、用户补充和 AMD UG949 v2025.1，工程补充和修正见 source-notes.md；Xilinx 条件性规则及页码见 [xilinx-ug949.md](xilinx-ug949.md)。原文 L0–L3 标签存在前后不一致，此处使用稳定的 R01–R12 编号。

## R01 命名与端口（默认；协议名称必须保留）

| 对象 | 新建代码约定 | 示例/边界 |
|---|---|---|
| 自定义输入/输出 | `i_` / `o_` | `i_clk`、`i_rst`、`o_result_data` |
| 输入/输出寄存器 | `ri_` / `ro_` | 内部名字；外部端口仍 `i_`/`o_` |
| 其他寄存器/组合信号 | `r_` / `w_` | 按实际驱动方式区分，`logic` 不代表一定是寄存器 |
| 参数/localparam/状态值 | `P_` | `P_DATA_W`、`P_ST_IDLE` |
| 数组 | `_array` | `r_weight_array` |
| 跨域信号 | 有清晰的 `cdc` 语义标签 | 如 `r_cdc_flag_sync1`；先遵守端口与存储类别，不堆叠互斥前缀 |
| 带有效标识的数据 | `i_xx_data` / `i_xx_dvalid`，内部同步传递 | 输出对应 `o_`；多操作数共用 valid 时明确它覆盖的同拍 bundle |
| 标准协议 | 保留协议/项目原名 | `s_axis_tdata/tvalid/tready`、`m_axi_awaddr` 等，不加自定义命名要求 |

既有公开端口、IP 接口及被约束文件引用的对象，不为风格批量改名。命名是语义标识，不能代替对驱动类型或 CDC 结构的检查。

## R02 复位与时序块（默认 + 必要）

- 先判断每组寄存器是否需要运行时复位。需要复位的普通单时钟逻辑默认 `always_ff @(posedge i_clk)` / `always @(posedge i_clk)`，块内 `if (i_rst)`，复位高有效、同步到该时钟，并优先于时钟使能；不能把 `if (enable)` 放在复位条件外面而使复位受 enable 限制。
- FSM、valid/占用、指针及协议控制恢复安全值；计数器按重新启动/保留语义处理。只在 payload 内容在 valid 为真或被读取前已确定覆盖、且 invalid 数据不会影响控制/外部接口时，才可省去其运行时复位。不得删除明确要求的输出清零、擦除或中途复位语义；用仿真验证首次启动和流水中复位。
- 有复位与无复位的寄存器分到不同过程。仅删掉复位分支中的部分赋值，而功能赋值仍放在 `else` 下，会使这些变量在复位期间保持，可能推断由复位控制的 CE；它不等于自由运行的无复位流水。配置 INIT、运行时复位和整块存储清除分别说明（UG949 pp.40–45、56）。
- 原有异步低有效复位、器件原语或复位控制器保留既定行为；需要转换时说明各时钟域的复位释放方案，不能只把 `negedge rst_n` 从敏感表删除。
- 不用组合生成的时钟驱动新逻辑；普通门控优先时钟使能，专用时钟管理按目标器件使用。
- 时序变量用 `<=`；组合结果用 `=`。同一寄存器不能在不同 always 块中多重赋值，包含复位块与功能块之间的多驱动。
- 为降低单块复杂度，新写的时序 `always` 块默认至多更新 3 个独立寄存器变量（按变量计，向量整体算一个）；超过时按数据、控制或通道职责拆块。相关 data/valid/sideband、状态/计数器可因同一原子更新关系保留在一块，但应说明理由；不得拆成多驱动，也不得让拆分改变原有复位、使能或边沿行为。不要把无关状态拼成向量/结构体以规避上限；RAM/DSP 模板、同一协议 bundle 或资源推断需要保留完整过程时，记录具体例外。拆成不同过程但保持相同 clock/reset/CE 不会因块数本身增加控制集；不要人为派生不同控制来配合拆块。该上限来自团队要求，UG949 未规定每块最多 3 个信号；它不代替时序分析。

### 复位与业务清零分离（用户要求）

- 有运行时复位的寄存器，时序过程使用独立、优先的 `if (i_rst)` 分支。该分支只做复位初始化。复位判断只引用本时钟域的复位信号。`abort`、`flush`、事务结束、超时、回卷和软件清零均用独立业务条件表达，例如 `w_abort` 和 `w_done`。
- 在同一个时序过程中，把业务清零写成复位之后的 `else if`，继续使用后续分支表达正常更新。禁止 `if (i_rst || w_abort)`、`if (i_rst | w_abort)`，也禁止把业务控制并入别名再充当复位。真实复位源的汇聚放在复位控制器或边界，并按目标域的复位释放契约处理。信号名称包含 `reset` 的会话命令仍按其业务语义处理。
- 同一寄存器只有一个时序驱动。保持业务清零与更新原有的同拍优先级、未命中保持和已有时钟边沿。此规则无需新建组合次值过程、派生使能或增加流水级。已有组合次值设计可以按原职责使用。保持已有异步复位敏感表和释放行为。检查复位、业务清零与更新同时成立的情形。

```verilog
always @(posedge i_clk) begin
    if (i_rst) begin
        r_count <= 16'd0;
    end else if (w_abort) begin
        r_count <= 16'd0;
    end else if (w_enable) begin
        r_count <= r_count + 16'd1;
    end
end
```

```verilog
assign w_count_next = w_clear_count ? 16'd0 : w_count_advanced;

always @(posedge i_clk) begin
    if (i_rst)
        r_count <= 16'd0;
    else
        r_count <= w_count_next;
end
```

此处 `w_count_advanced` 是组合次值，包含未更新时保持 `r_count` 的路径。

### 时序块仅保留单一条件决策链（用户要求）

每个时序 `always` / `always_ff` 块使用单一 `if / else if / else` 决策链。链内可嵌套，但任何同级语句序列均不得包含相互独立的多个 `if`，包括复位 `else` 内部。无条件寄存和寄存器保持可按契约保留，不为凑齐末尾 `else` 添加空分支或自赋值。此要求只约束可综合时序 RTL，不限制 testbench 或组合逻辑表达。

需要独立同拍更新的寄存器分到不同过程；每个寄存器只保留一个驱动过程。拆分后读取的仍是同一时钟沿之前的寄存器值，保持复位、使能、握手和输出延迟。先确认同一寄存器的后写覆盖优先级；不得机械串接 `else if`，也不得新增寄存级。例：计数达到阈值时，计数器递增与锁定标志置位必须同拍发生，可拆成下列两块：

```verilog
always @(posedge i_clk) begin
    if (i_rst) r_count <= 0;
    else if (i_measure && (r_count < P_LIMIT)) r_count <= r_count + 1'b1;
end
always @(posedge i_clk) begin
    if (i_rst) r_locked <= 0;
    else if (i_measure && (r_count >= (P_LIMIT - 1))) r_locked <= 1;
end
```

验证时覆盖条件同时成立、阈值边沿、饱和、复位与使能重叠；确保原有并行更新及同一寄存器的赋值优先级保持。此规则来自用户偏好，不能声称其本身改善时序或资源。

## R03 输入、输出边界（默认；已有时序契约优先）

- 新普通数据通路优先输入打一拍，用 `ri_` 承载数据及配套 valid/控制；输出由 `ro_` 寄存器驱动，使用 `assign o_xx = ro_xx`。
- 不能给时钟或复位“统一打一拍”。不能只寄存 data 而漏寄存 valid、last、keep、地址、标签等对应信息。
- AXI/AXI-Stream、存储读端口、零周期状态路径或已经约定的延迟，按各自协议处理。增加寄存器必须同时定义容量、握手/背压和延迟变化。
- 组合输出若由接口契约或经说明的实现决定，可以保留；检查组合环、关键路径和建立/保持约束。不能因默认规则改变有效握手。
- `assign` 是连续连接，不是流水线，也不能保证降低延时；只有实际的寄存边界和实现报告能支撑时序结论。

## R04 data/valid、使能与握手（必要）

- 每级数据和有效标志一一对应。流水线有 N 级，就明确采样边沿及有效传递关系；有气泡仍传递对应的无效状态。
- 无背压的模块：每拍接受有效输入，data 可以在 invalid 时保持，valid 要按既定流水传播。
- 带 ready/valid 的模块：仅在相应 `valid && ready` 时接收/发送；等待期间保持 valid 和相关数据/旁带稳定；流水级停顿时所有相关状态一致保持。
- AXI-Stream 源端不能等 `TREADY` 才决定拉高 `TVALID`。给 `TREADY` 增加寄存器时需要匹配缓冲容量/握手设计，不能将三个信号独立打一拍。
- req/ack 的电平/脉冲、谁先发起、保持到何时、超时/重试规则必须来自接口规格；不能凭信号名假定协议。
- 时钟使能或流水 stall 必须同时覆盖数据、valid 与随行状态；仿真覆盖连续输入、气泡、连续/解除背压和流水中复位。
- 需要保持数据、AXIS 阻塞或功耗优化时保留 CE；数据在 invalid 时不被使用且允许变化时，可评估常更新/确定赋值是否减少低扇出控制集。不能为减少 CE 而改变已声明的 invalid 输出保持行为。

## R05 位宽、有符号与定点运算（必要）

- 列清楚输入和各中间结果的位宽/符号；参数范围如宽度至少 1 应明确，不生成零位向量或负范围。
- 全精度 W_A×W_B 的乘积准备 W_A+W_B 位；加法先对两个操作数正确扩位再运算；N 项累加根据输入范围计算增长位数，必要时加 `ceil(log2(N))` 位。
- 明确每个表达式的求值宽度及符号。将结果赋给更宽的左值不能替代对截断、切片和混合 signed/unsigned 表达式的检查。
- 位切片/拼接容易改变符号属性；在需要有符号运算的边界显式声明或转换，再做符号扩展。不要只在运算完成后对已经溢出的结果 `$signed`。
- 控制常量显式指定位宽；SV 的上下文全零 `'0`、Verilog 的复制零常量均要与语言版本匹配，避免无尺寸常量意外参与数据运算。
- 定点格式写成“总位宽 W、符号、分数位 F”，避免含糊的 Q15。乘法分数位相加；加法先对齐二进制小数点。
- 截位位置、舍入（如就近/截断）、饱和/回卷必须明确；最终每移一位都会改变数值解释，不能只按输出位宽机械裁剪。
- 最小负数、最大正数、负负相乘、两路最大乘积相加、跨符号零附近是重点边界。性能目标不能成为未经说明缩位或降精度的理由。

## R06 FSM 与控制（必要 + 建议）

- 新 FSM 建议分为状态寄存、下一状态组合逻辑、输出/动作逻辑；两段式或其他可验证结构可按项目采用。
- FSM 的状态更新/转移判定与宽数据处理、算术、缓存搬运等 datapath 更新分开编排；状态仅产生清晰的控制/使能，datapath 按这些控制更新。若小型控制器把状态与少量动作合并更清晰，可合并但不能埋入多层、难审阅的数据处理流程。不要为了分离而复制状态译码或引入额外组合级。
- **组合赋值完整性（必要）**：`always_comb` / `always @*` 中逐个检查被赋值的信号和临时变量（含向量各位、嵌套分支和零次迭代路径）。`if/else if` 链优先写最终 `else` 并显式赋值；若在块入口已对所有目标设定符合接口契约的完整默认值，允许分支仅覆盖所需信号并省略 `else`。最终 `else` 存在也不等于完整，若其中漏了某个输出仍会保留旧值。空分支、自赋值（如 `w_data = w_data`），或只清 `valid` 却遗漏 `data`，都不能替代组合默认值。`always_comb` 不保证工具替你补赋值。FSM 的 `next_state = current_state` 是从另一个状态寄存器取值，不是自反馈。
- 组合 `case` 要有 `default`；FSM 定义非法状态恢复（组合默认值可作为该路径动作）。不以 `unique case` 或综合指令代替完整赋值或恢复逻辑。仅时序块可用省略 `else` 表达有意保持，不要求为时钟使能加 `q <= q`；有意使用电平敏感锁存器则另行按规格说明并验收，不得与误推断混同。
- **条件显式分组（必须）**：`if/else if`、`?:` 以及驱动控制的布尔表达式中，混用不同运算符时用内层 `()` 标出实际分组；尤其是 `&&` 与 `||`、比较与逻辑、按位/归约与比较、移位/算术与比较。简单单一条件不必重复加括号。`if (...)` 的语法括号不算分组。括号不是改变优先级的理由：例如保持 `a || b && c` 的原语义应写 `a || (b && c)`，不是 `(a || b) && c`。复杂表达式可提取有意义的中间连线，但不改变位宽、符号、X 语义、时序或 `if/else if` 的分支先后；发现原意和现有语义可能不同，先核对规格及测试。
- **禁止嵌套或串联三目（用户要求）**：`?:` 只用于简单的二选一。不把多级优先级选择藏在一条赋值或拼接中，也不靠逐级拆 wire 保留三目链。复杂逻辑按职责拆成有语义的 `w_` 条件、候选值和最终选择；有优先级时用清楚的 `if / else if / else`，确认为互斥选择时可用 `case`。多字段拼接先计算复杂字段，再按字段排列。例如，时间戳选择把“失效清零、新事件优先、有效历史值、默认清零”写成显式优先级链；回包时序块只在请求有效的同一个边沿锁存结果。改写既有 `?:` 时核对位宽、符号和四态语义；若选择位可能为 X/Z，`if` 与 `?:` 不保证等价，应先查清有效性约定，不机械替换。
- 有仲裁优先级时明确保留顺序；只有互斥/译码语义成立时才改成并行 `case`。不照搬 `casex`、`full_case`、`parallel_case`；通配/互斥声明必须有功能前提，仿真覆盖多条件同时为真和未知/非法输入，不能以综合优化提示改变优先级。
- 非阻塞赋值的新结果在本边沿后生效；不能在同一时序块内按软件顺序依赖刚赋值的数据。
- 输出基于当前状态还是下一状态，取决于接口的逐拍定义。禁止把来源示例的 `case (r_st_next)` 当成通用模板；用时序表检查首拍、末拍和状态切换边界。
- 只有规格要求或存在明确等待风险时设计超时。已知时钟频率与时限后换算周期和计数器位宽，定义边界、溢出及超时动作；不能任意添加会改变协议的超时退出。
- 完成数据计算后再消费，必要时快照保存整帧结果；不能发送高低字节时从仍在更新的实时流水结果分别取值。

### 组合判定范例

```systemverilog
// i_force 优先于 enable；都不匹配时由最终 else 驱动所有输出。
always_comb begin
    if (i_force || (i_sel && i_enable)) begin
        o_data  = i_a;
        o_valid = 1'b1;
    end else if (i_enable) begin
        o_data  = i_b;
        o_valid = 1'b1;
    end else begin
        o_data  = '0;
        o_valid = 1'b0;
    end
end
```

若采用默认值写法，把最后两项赋值移到块入口、删除最终 `else`；非匹配路径仍使用同一回退。Verilog-2001 用 `always @*`，并用匹配目标位宽的常量（上例的 `'0` 是 SV 写法）。

## R07 CDC（必要；按对象分类）

- 先确定源/目的时钟、频率关系、脉宽、采样事件与允许丢失程度。没有跨域就不插入 CDC 结构。
- 稳定的单比特电平可使用目的域同步器链；同步级数及属性按项目/器件/可靠性要求，不能保证任意两级结构都足够。
- 脉冲使用能保证捕获的展宽、toggle 或握手；快到慢的单拍脉冲不能只串两级寄存器。
- 多比特相关数据使用握手快照、异步 FIFO 或已证明一致性的编码方案；不对总线各位独立同步后直接组合使用。
- Xilinx 的 XPM、`ASYNC_REG` 或约束仅在目标平台明确时使用。按电平、脉冲、复位、相关总线/数据流选择对应 XPM 或已验证结构；同步器级数须符合速率、延迟和可靠性目标，不以“总是两级”替代判断。异步 FIFO/握手不能用逐位同步替换。
- 不复制同步链寄存器或从亚稳态级分叉；确需减小同步后扇出时，在稳定的同步链之后按协议增加普通寄存/分发层并核对新增延迟。`ASYNC_REG` 不证明总线一致性。不得为消除告警而随意加 false path，CDC 静态检查、时序约束和功能仿真各自说明覆盖范围。

## R08 数组、RAM 与语言版本（默认 + 条件性）

- 面向多厂商 FPGA 的可综合 RTL 默认避免 `initial`、寄存器声明赋初值及 INIT/GSR 上电依赖。需要确定初态的控制/输出采用显式复位或明确的启动流程；允许不复位的 payload 必须在使用前覆盖并经 valid 隔离，不假设器件配置后自动为零。
- 配置初始化只作为当前功能确需的条件性例外，例如 ROM/存储预置；须确认目标厂商、器件与综合/仿真工具支持，记录初始化文件、用途、移植限制和运行时恢复方式。不能因为某厂商支持便主动采用，也不能把“不推荐”错误表述成所有 FPGA 都不可综合。testbench 的 `initial` 不受本条限制。
- SV unpacked array 可在目标工具支持时使用 `'{default:'0}` 或兼容的整体赋值；确认维度、方向、元素类型相匹配。
- `.v`/Verilog-2001 不使用 SV 的数组 assignment pattern、`logic`、`always_ff`、`typedef enum` 等；用合法的声明和有界 for 循环逐元素处理寄存器数组。
- 工具不支持某种合法 SV 写法时改为同语义的兼容写法，不能用“标准允许”冒充目标工具验证通过。
- 大型权重/缓存/ROM、BRAM/URAM 与 DSP 数据链优先保留所需资源推断结构。逐元素复位可能改变推断，先区分复位控制/valid、输出寄存器与清除整个存储内容的真实要求。
- 若必须清零整块存储，设计可验证的逐地址清零流程及完成状态，或使用器件支持且规格允许的方案；不能静默省去清零语义。
- 明确 RAM 读延迟、端口/时钟、读写冲突和初始化语义。优先用对应系列 HDL 模板推断；必要时选 XPM/IP/原语。RAM 阵列及期望吸收的输出寄存器尽量同层级；异步复位、前级多重扇出、反馈或 KEEP 可能阻碍输出寄存器吸收，综合后检查实际结构。
- 深延迟线评估 SRL，乘加评估 DSP 内部流水及复位/置位限制，宽深存储器评估级联和读取延迟；不照搬其他系列的 DSP 宽度、URAM 可用性或 RAM 级联参数。为布线跨区而需要真实 FF 的流水也不能盲目压成 SRL。

## R09 结构、注释与排版（建议）

推荐逻辑分区：模块说明与参数/I/O → 输入寄存 → 输出寄存和连接 → 常量/状态 → 子模块 → FSM → 组合/时序逻辑 → 数组相关逻辑。参数必须放在被引用之前等语言要求优先；已有模块不为顺序偏好重排。

模块头交代功能、复位、格式、接口、边沿延迟/吞吐及关键状态。复杂运算解释二进制小数点、舍入/溢出及流水对应关系。每段声明/连接/赋值局部对齐，长名称或表达式换行；名称尽量简洁，32 字符是建议。

- 编写前先明确目标时钟、输入吞吐、允许延迟/背压和时序约束；按运算层级规划流水边界，避免将长加法链、宽比较链或多级优先 mux 堆成单周期关键路径。没有接口允许的延迟预算时，不自行插入寄存器。
- 区分可读性重构与硬件缩短路径。命名 `w_`、分行、抽组合过程或将三目改为分支都不增加物理寄存边界，综合后可能仍是同一条路径。优化单拍深度时，先识别串行依赖，考察可独立的判定是否可并行预译码；只在证明互斥或保持原优先级后调整选择结构。确需流水时按允许的延迟设计，整组核对 data/valid、时间戳、复位、使能、保持及跨域握手。用同一器件、时钟约束下的相同逻辑路径比较逻辑级数、逻辑/布线延迟和 slack，不以源码行数判断时序。
- 同时考虑物理实现：相关控制和数据尽量局部，谨慎使用驱动大量负载的全局 enable/reset/select，避免无依据的超宽交叉 mux 和高扇出分发树。资源共享可能增加 mux 深度，复制逻辑可能增加面积与拥塞；根据时序/综合/实现报告权衡，不把任一技巧作为绝对规则。
- 完成 RTL 仿真后，性能目标还应以目标器件、约束和 Vivado 综合/实现报告核验；关注关键路径起止点、逻辑级数、扇出、拥塞及建立/保持裕量。无报告时只描述设计意图，不宣称 Fmax 或布线已改善。

层级优先围绕功能与时序边界组织；不要在期望被原语吸收的 RAM/DSP 寄存器间随意插层或探测。I/O 和时钟资源尽量靠近顶层共享；不为“保留结构”默认加 KEEP_HIERARCHY/DONT_TOUCH。

原文“每10行至少1个AI标记”是可选风格项，不作为验收门槛；不生成没有工程价值的 AI 标记、虚构作者/审核者或历史版本说明。

## R10 复杂计算与 Transformer 范围（必要边界）

- 用户可提供完整接口、例化方式、目标器件/频率、MATLAB/软件量化参考、功能/性能指标。对未知项采用明确且不改变契约的假设，只就阻塞事项提问。
- 大模块可按可单独验证的运算、存储访问和控制分解；优化需保持数值与交易对应关系。
- 源文标题包含 Transformer，但没有规定 Q/K/V、attention、softmax、归一化、矩阵分块、访存调度或量化算法。具体实现来自当前需求和参考模型，不能伪称源文已有结论。
- 未跑对应工具就不报告某个频率、时序裕量、DSP/BRAM 数量或固定资源映射；没有这些工具不妨碍交付标明验证边界的可综合 RTL。

## R11 交付前验证（与本次改动匹配）

1. 首先运行项目现有命令；带包、include、宏和多个源文件时复用完整 filelist，禁止省略依赖后宣称代码错误或验证通过。
2. 无项目配置的小模块可用以下示例命令，替换 TOP/路径并带全依赖：

```bash
# SystemVerilog：语法/展开与 lint
iverilog -g2012 -s TOP -o /tmp/design-check.vvp rtl.sv
verilator --lint-only --top-module TOP -Wall rtl.sv
# Verilog-2001：检查语言兼容性；若 testbench 是 SV，应先独立检查 RTL
iverilog -g2001 -s TOP -o /tmp/design-check.vvp rtl.v
# 仿真：运行带明确 pass/fail 条件的自检 testbench
iverilog -g2012 -s tb_TOP -o /tmp/design-test.vvp rtl.sv tb_TOP.sv
vvp /tmp/design-test.vvp
```

运行时使用工作目录内的专用临时路径；上面的 `/tmp` 仅示意编译产物，不覆盖项目文件。项目配置允许 lint waiver 时记录具体原因，不能全局关闭告警掩盖问题。

3. 重点检查复位及中途复位、data/valid 配对、气泡、吞吐、背压、帧边界、边界数值和参数最小值；按功能选择测试，不为无关代码创建整套测试。改动组合判定时，逐信号/位核对所有路径的赋值；仿真至少覆盖命中后切换到所有条件均不命中（检查 data 和 valid 回到约定默认值）、各分支、可重叠分支的优先级，以及能区分括号分组的输入。检查 lint/综合中的 latch 推断告警，不可全局屏蔽；没有告警不代表赋值完整，不得用来跳过路径核对和仿真。
4. Xilinx 项目按当前设计阶段选择报告：细化后的 `report_methodology`；综合后的资源推断、`report_control_sets`、`report_high_fanout_nets`、`report_drc`、`report_cdc`；实现后的完整时序/约束、拥塞及方法论报告。先修复或有据豁免严重问题，新增重要模块或改变时钟/约束后复查。具体阶段和命令支持见 UG949 参考，不对小改动无差别重跑全流程。
5. lint/仿真不等于综合/布局布线/STA/CDC 完成；各检查只报告实际执行的命令与结论。失败时先修复再交付，工具缺失则说明对应检查未执行。

## R12 规则冲突与审查表达（必要）

- 功能/接口确定性、器件合法性及有效的资源映射高于团队默认结构，默认结构高于排版偏好。明确的用户覆盖只作用于其指定范围，不扩张为全项目规范修改授权。
