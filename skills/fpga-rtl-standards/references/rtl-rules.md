# FPGA RTL 规则清单

自动调用仅适用于生成、修改或重构可综合 RTL；仅有测试/验证代码、讲解或独立审查的任务不自动触发。混合任务只约束其中可综合 RTL。

“默认”适用于新建、接口未固定的模块；“必要”用于保证所声明的功能和协议正确；“建议”可按项目覆盖。来源为用户 PDF，工程补充和修正见 source-notes.md。原文 L0–L3 标签存在前后不一致，此处使用稳定的 R01–R12 编号。

## R01 命名与端口（默认；协议名称必须保留）

| 对象 | 新建代码约定 | 示例/边界 |
|---|---|---|
| 自定义输入/输出 | `i_` / `o_` | `i_clk`、`i_rst`、`o_result_data` |
| 输入/输出寄存器 | `ri_` / `ro_` | 内部名字；外部端口仍 `i_`/`o_` |
| 其他寄存器/组合信号 | `r_` / `w_` | 按实际驱动方式区分，`logic` 不代表一定是寄存器 |
| 参数/localparam/状态值 | `P_` | `P_DATA_W`、`P_ST_IDLE` |
| 数组 | `_array` | `r_weight_array` |
| 跨域信号 | 有清晰的 `cdc` 语义标签 | 如 `r_cdc_flag_sync1`；先遵守端口与存储类别，不堆叠互斥前缀 |
| 带有效标识的数据 | `i_xx_data` / `i_xx_dvalid`，内部同步传递 | 输出对应 `o_`；多操作数共用 valid 时明确它覆盖的同拍 bundle |
| 标准协议 | 保留协议/项目原名 | `s_axis_tdata/tvalid/tready`、`m_axi_awaddr` 等，不加自定义命名要求 |

既有公开端口、IP 接口及被约束文件引用的对象，不为风格批量改名。命名是语义标识，不能代替对驱动类型或 CDC 结构的检查。

## R02 复位与时序块（默认 + 必要）

- 新普通单时钟逻辑默认 `always_ff @(posedge i_clk)` / `always @(posedge i_clk)`，块内 `if (i_rst)`，复位高有效、同步到该时钟。
- 复位优先级显式；FSM 回到安全初态，valid/占用/计数/控制清零，依赖确定初值的数据显式初始化。控制有任意初态就安全的结论必须有依据。
- 原有异步低有效复位、器件原语或复位控制器保留既定行为；需要转换时说明各时钟域的复位释放方案，不能只把 `negedge rst_n` 从敏感表删除。
- 不用组合生成的时钟驱动新逻辑；普通门控优先时钟使能，专用时钟管理按目标器件使用。
- 时序变量用 `<=`；组合结果用 `=`。同一寄存器不能在不同 always 块中多重赋值，包含复位块与功能块之间的多驱动。

## R03 输入、输出边界（默认；已有时序契约优先）

- 新普通数据通路优先输入打一拍，用 `ri_` 承载数据及配套 valid/控制；输出由 `ro_` 寄存器驱动，使用 `assign o_xx = ro_xx`。
- 不能给时钟或复位“统一打一拍”。不能只寄存 data 而漏寄存 valid、last、keep、地址、标签等对应信息。
- AXI/AXI-Stream、存储读端口、零周期状态路径或已经约定的延迟，按各自协议处理。增加寄存器必须同时定义容量、握手/背压和延迟变化。
- 组合输出若由接口契约或经说明的实现决定，可以保留；检查组合环、关键路径和建立/保持约束。不能因默认规则改变有效握手。
- `assign` 是连续连接，不是流水线，也不能保证降低延时；只有实际的寄存边界和实现报告能支撑时序结论。

## R04 data/valid、使能与握手（必要）

- 每级数据和有效标志一一对应。流水线有 N 级，就明确采样边沿及有效传递关系；有气泡仍传递对应的无效状态。
- 无背压的模块：每拍接受有效输入，data 可以在 invalid 时保持，valid 要按既定流水传播。
- 带 ready/valid 的模块：仅在相应 `valid && ready` 时接收/发送；等待期间保持 valid 和相关数据/旁带稳定；流水级停顿时所有相关状态一致保持。
- AXI-Stream 源端不能等 `TREADY` 才决定拉高 `TVALID`。给 `TREADY` 增加寄存器时需要匹配缓冲容量/握手设计，不能将三个信号独立打一拍。
- req/ack 的电平/脉冲、谁先发起、保持到何时、超时/重试规则必须来自接口规格；不能凭信号名假定协议。
- 时钟使能或流水 stall 必须同时覆盖数据、valid 与随行状态；仿真覆盖连续输入、气泡、连续/解除背压和流水中复位。

## R05 位宽、有符号与定点运算（必要）

- 列清楚输入和各中间结果的位宽/符号；参数范围如宽度至少 1 应明确，不生成零位向量或负范围。
- 全精度 W_A×W_B 的乘积准备 W_A+W_B 位；加法先对两个操作数正确扩位再运算；N 项累加根据输入范围计算增长位数，必要时加 `ceil(log2(N))` 位。
- 明确每个表达式的求值宽度及符号。将结果赋给更宽的左值不能替代对截断、切片和混合 signed/unsigned 表达式的检查。
- 位切片/拼接容易改变符号属性；在需要有符号运算的边界显式声明或转换，再做符号扩展。不要只在运算完成后对已经溢出的结果 `$signed`。
- 控制常量显式指定位宽；SV 的上下文全零 `'0`、Verilog 的复制零常量均要与语言版本匹配，避免无尺寸常量意外参与数据运算。
- 定点格式写成“总位宽 W、符号、分数位 F”，避免含糊的 Q15。乘法分数位相加；加法先对齐二进制小数点。
- 截位位置、舍入（如就近/截断）、饱和/回卷必须明确；最终每移一位都会改变数值解释，不能只按输出位宽机械裁剪。
- 最小负数、最大正数、负负相乘、两路最大乘积相加、跨符号零附近是重点边界。性能目标不能成为未经说明缩位或降精度的理由。

## R06 FSM 与控制（必要 + 建议）

- 新 FSM 建议分为状态寄存、下一状态组合逻辑、输出/动作逻辑；两段式或其他可验证结构可按项目采用。
- 组合逻辑先完整默认赋值，case 有 `default` 并定义非法状态恢复；不以 `unique case` 或综合指令代替恢复逻辑。
- 非阻塞赋值的新结果在本边沿后生效；不能在同一时序块内按软件顺序依赖刚赋值的数据。
- 输出基于当前状态还是下一状态，取决于接口的逐拍定义。禁止把来源示例的 `case (r_st_next)` 当成通用模板；用时序表检查首拍、末拍和状态切换边界。
- 只有规格要求或存在明确等待风险时设计超时。已知时钟频率与时限后换算周期和计数器位宽，定义边界、溢出及超时动作；不能任意添加会改变协议的超时退出。
- 完成数据计算后再消费，必要时快照保存整帧结果；不能发送高低字节时从仍在更新的实时流水结果分别取值。

## R07 CDC（必要；按对象分类）

- 先确定源/目的时钟、频率关系、脉宽、采样事件与允许丢失程度。没有跨域就不插入 CDC 结构。
- 稳定的单比特电平可使用目的域同步器链；同步级数及属性按项目/器件/可靠性要求，不能保证任意两级结构都足够。
- 脉冲使用能保证捕获的展宽、toggle 或握手；快到慢的单拍脉冲不能只串两级寄存器。
- 多比特相关数据使用握手快照、异步 FIFO 或已证明一致性的编码方案；不对总线各位独立同步后直接组合使用。
- Xilinx 的 XPM、`ASYNC_REG` 或约束仅在目标平台明确时使用。不得为消除告警而随意加 false path，CDC 静态检查、时序约束和功能仿真各自说明覆盖范围。

## R08 数组、RAM 与语言版本（默认 + 条件性）

- 新普通寄存器小数组不用可综合 `initial` 初始化；按复位/功能规格在同一个时序驱动过程中更新。
- SV unpacked array 可在目标工具支持时使用 `'{default:'0}` 或兼容的整体赋值；确认维度、方向、元素类型相匹配。
- `.v`/Verilog-2001 不使用 SV 的数组 assignment pattern、`logic`、`always_ff`、`typedef enum` 等；用合法的声明和有界 for 循环逐元素处理寄存器数组。
- 工具不支持某种合法 SV 写法时改为同语义的兼容写法，不能用“标准允许”冒充目标工具验证通过。
- 大型权重/缓存/ROM、BRAM/URAM 与 DSP 数据链优先保留所需资源推断结构。逐元素复位可能改变推断，先区分复位控制/valid、输出寄存器与清除整个存储内容的真实要求。
- 若必须清零整块存储，设计可验证的逐地址清零流程及完成状态，或使用器件支持且规格允许的方案；不能静默省去清零语义。
- 明确 ROM/上电初始化、`readmemh`、IP/原语属于单独的资源需求；不将默认禁止 `initial` 推广成不能做 ROM 初始化，也不自动加入这些做法。

## R09 结构、注释与排版（建议）

推荐逻辑分区：模块说明与参数/I/O → 输入寄存 → 输出寄存和连接 → 常量/状态 → 子模块 → FSM → 组合/时序逻辑 → 数组相关逻辑。参数必须放在被引用之前等语言要求优先；已有模块不为顺序偏好重排。

模块头交代功能、复位、格式、接口、边沿延迟/吞吐及关键状态。复杂运算解释二进制小数点、舍入/溢出及流水对应关系。每段声明/连接/赋值局部对齐，长名称或表达式换行；名称尽量简洁，32 字符是建议。

原文“每10行至少1个AI标记”是可选风格项，不作为验收门槛；不生成没有工程价值的 AI 标记、虚构作者/审核者或历史版本说明。

## R10 复杂计算与 Transformer 范围（必要边界）

- 用户可提供完整接口、例化方式、目标器件/频率、MATLAB/软件量化参考、功能/性能指标。对未知项采用明确且不改变契约的假设，只就阻塞事项提问。
- 大模块可按可单独验证的运算、存储访问和控制分解；优化需保持数值与交易对应关系。
- 源文标题包含 Transformer，但没有规定 Q/K/V、attention、softmax、归一化、矩阵分块、访存调度或量化算法。具体实现来自当前需求和参考模型，不能伪称源文已有结论。
- 未跑对应工具就不报告某个频率、时序裕量、DSP/BRAM 数量或固定资源映射；没有这些工具不妨碍交付标明验证边界的可综合 RTL。

## R11 交付前验证（与本次改动匹配）

1. 首先运行项目现有命令；带包、include、宏和多个源文件时复用完整 filelist，禁止省略依赖后宣称代码错误或验证通过。
2. 无项目配置的小模块可用以下示例命令，替换 TOP/路径并带全依赖：

```bash
# SystemVerilog：语法/展开与 lint
iverilog -g2012 -s TOP -o /tmp/design-check.vvp rtl.sv
verilator --lint-only --top-module TOP -Wall rtl.sv
# Verilog-2001：检查语言兼容性；若 testbench 是 SV，应先独立检查 RTL
iverilog -g2001 -s TOP -o /tmp/design-check.vvp rtl.v
# 仿真：运行带明确 pass/fail 条件的自检 testbench
iverilog -g2012 -s tb_TOP -o /tmp/design-test.vvp rtl.sv tb_TOP.sv
vvp /tmp/design-test.vvp
```

运行时使用工作目录内的专用临时路径；上面的 `/tmp` 仅示意编译产物，不覆盖项目文件。项目配置允许 lint waiver 时记录具体原因，不能全局关闭告警掩盖问题。

3. 重点检查复位及中途复位、data/valid 配对、气泡、吞吐、背压、帧边界、边界数值和参数最小值；按功能选择测试，不为无关代码创建整套测试。
4. lint/仿真不等于综合/布局布线/STA/CDC 完成；各检查只报告实际执行的命令与结论。失败时先修复再交付，工具缺失则说明对应检查未执行。

## R12 规则冲突与审查表达（必要）

- 功能/接口确定性高于默认结构，默认结构高于排版偏好。明确的用户覆盖只作用于其指定范围，不扩张为全项目规范修改授权。
- 发现违反必要正确性约束时修复或给出可定位的问题，不把协议损坏当成命名例外。不把合法的语言/器件选择标成“违规”。
- 生成/修改的简短说明可采用：假设与例外；输入 E0 到输出 En 的关系、吞吐和反压；已运行检查与未验证项。
- 纯审查以发现为主，按严重性排序并标注文件和行号。只在用户要求修改时写入文件。
